# 🧠 MEMORY.md — Learned Invariants & Failure Post-Mortems

### 🧠 Learned Invariants & Failure Post-Mortems

- **[26-10-19 · app/api/resume]**: Endpoint PDF tak pernah tereksekusi — `/api/resume` dijawab 404 lokal; setelah itu terungkap `?lang=ja` juga lolos validasi → **Root Cause**: dua lapis. (1) Matcher middleware tidak mengecualikan `/api`, dan `api` (3 huruf) cocok dengan pola LANGUAGE_TAG, sehingga request di-rewrite ke `/{locale}/api/resume` lalu ditangkap `[...rest]`; handler tidak pernah dipanggil. (2) Handler memakai `isLocale` yang menerima `ja`, locale berkamus tanpa rute (`dynamicParams=false`), jadi Chromium memaginasi dokumen 404 tanpa error → **Invariant Rule**: matcher middleware wajib mengecualikan `/api` karena endpoint bukan halaman, dan setiap permukaan pembangun URL halaman memakai `isPublishedLocale`; buktikan endpoint dengan request nyata yang hanya bisa mencapai status benar bila rute dieksekusi (`?lang=ja` → 400 JSON), bukan dengan membaca kode.

- **[26-10-19 · CI/lighthouse]**: job `lighthouse` selalu gagal di langkah `pnpm run test:lighthouse` → **Root Cause**: perintah Lighthouse hanya ada di README sebagai `npx @lhci/cli@0.15.1 …`, tidak pernah didefinisikan sebagai script `package.json`, sehingga workflow memanggil nama yang tidak ada → **Invariant Rule**: setiap script yang direferensikan `.github/workflows/` harus ada di `package.json`; saat mengubah workflow, jalankan `pnpm run <script>` untuk membuktikan namanya resolvable.

- **[26-10-19 · i18n/locales]**: Menambahkan `"ja"` ke `lib/locale.ts` tanpa mendaftarkan kamusnya meledakkan semua `Record<Locale, …>` (dictionary barrel, `error-copy.ts`, `NotFoundView`) → **Root Cause**: `Locale` adalah union tuple, sehingga menambah anggota menuntut key baru di _setiap_ pemetaan per-locale; barrel `lib/content/index.ts` hanya memuat `en`/`id`, sementara `ja.ts` belum diimpor → **Invariant Rule**: menambah locale adalah perubahan lintas-file yang harus menyentuh `lib/locale.ts` + `lib/content/index.ts` + `lib/content/error-copy.ts` + boundary `not-found` dalam satu perubahan; jalankan `npx tsc --noEmit` sebelum menganggap locale siap.

- **[26-10-19 · build/lib/blog.ts]**: Halaman blog & feed mengimport `resolveSiteUrl` dari `@/lib/brand` → **Root Cause**: fungsi memang pindah ke `lib/content/index.ts`, import lama tak diperbarui saat file baru dibuat; ditambah `match[1]` regex bertipe `string | undefined` pada mode strict → **Invariant Rule**: fungsi publik hanya diekspor dari satu path canonical (`@/lib/content`); parser nama file tidak boleh mengindeks regex match tanpa guard `match[i] === undefined`.

- **[26-10-19 · test/vitest.config.ts]**: `npx vitest run` banyak gagal `connect ECONNREFUSED 127.0.0.1:3000` → **Root Cause**: pattern include default Vitest (`**/*.spec.ts`) menelan spec Playwright di `tests/` yang menuntut server berjalan → **Invariant Rule**: pisahkan runner — unit = `*.test.ts` (Vitest), E2E = `tests/*.spec.ts` (Playwright); file `.spec.ts` harus di-exclude dari Vitest.

- **[26-10-19 · test/ekspektasi]**: Tiga test basi gagal setelah perilaku berubah (isLocale ja, localeAlternates berisi ja, formatTemplate tanpa word boundary) → **Root Cause**: test ditulis sebelum `ja` diterapkan dan satu ekspektasi pun salah sejak awal (regex token memang menelan `{name}ing`) → **Invariant Rule**: saat mengubah perilaku domain (`locales`, regex publik), audit dan perbarui test pada commit yang sama; jangan biarkan ekspektasi basi menutupi regresi atau memaksa implementasi diubah.

- **[26-10-19 · lint]**: ESLint menolak apostrof mentah (`react/no-unescaped-entities`) dan assignment ke `module` → **Invariant Rule**: gunakan `&apos;` untuk copy JSX, hindari nama literal ES keyword (`module`) sebagai variabel; jalankan `pnpm lint` bersamaan dengan `tsc` karena keduanya menangkap kelas error berbeda.

- **[26-10-19 · perf/TBT]**: RevealSection (10 boundary client) dan pemisahan server/client Certificates hanya menurunkan median TBT ~600→~550ms; ablation tanpa Header tidak mengubah long task sama sekali → **Root Cause**: TBT halaman ini didominasi biaya framework — parse payload RSC inline (EvaluateScript ~90ms dari ~76KB payload) dan pass hidrasi React (~85ms), bukan jumlah komponen kita; ambang TBT Lighthouse ≈ 4× durasi task trace 1x, jadi desain kontrol harus menargetkan durasi task per-slice, bukan jumlah boundary → **Invariant Rule**: optimasi TBT di repo ini mulai dari ukuran payload & jumlah task ≥50ms yang diukur (`PerformanceObserver longtask` 1x), bukan dari menghilangkan komponen client kecil; uji perubahan dengan probe longtask lokal sebelum LHCI 6-run.

- **[26-10-19 · perf/DeferredIntegrations]**: Mount idle (`requestIdleCallback` + timeout 2s) untuk SW/Analytics/SpeedInsights masih memunculkan 4–6 task 50–200ms di dalam jendela TBT (_simulated_) karena idle callback menyala ~0.6s, jauh sebelum trace berakhir → **Root Cause**: jendela TBT Lighthouse bertahan sampai TTI (~4s), jadi "selesai saat idle" ≠ "di luar jendela pengukuran"; mount yang dipicu timer pendek tetap jatuh di dalam jendela → **Invariant Rule**: integrasi non-esensial (SW, Analytics, SpeedInsights) harus dimount pada interaksi pengunjung pertama, bukan pada idle callback/timer pendek; timer fallback minimal 12s.

- **[26-10-19 · perf/lingkungan-lokal]**: Dua batch LHCI berurutan pada build identik memberi median TBT 506 vs 704ms, dan Lighthouse melempar peringatan "device appears to have a slower CPU than Lighthouse expects" → **Root Cause**: proses Chrome/`next start` sisa batch sebelumnya tetap hidup dan merebut CPU saat batch berikutnya berjalan → **Invariant Rule**: sebelum dan antar batch LHCI, buru dan bunuh proses `chrome` serta `next start` yang tertinggal; bandingkan median (bukan satu run) dan jangan bandingkan batch yang cross lingkungan yang kotor.

- **[26-10-19 · perf/LCP-simulasi]**: LCP _simulated_ ~3.8s padahal LCP _observed_ hanya 0.8–2.3s; menunda font woff2 1.5s tidak mengubah LCP nyata sama sekali → **Root Cause**: Lantern menirukan jaringan lambat 4G atas rantai dokumen/CSS; elemen LCP adalah teks yang cat dengan font fallback (`font-display: swap`), bukan gambar/font → **Invariant Rule**: jangan buang waktu optimasi preload font/subsetting untuk LCP di repo ini; tindakan nyata adalah memangkas ukuran/round-trip dokumen (HTML 23.5KB gzip, payload RSC inline) dan CSS render-blocking (15KB gzip).

- **[26-10-20 · test/mutasi-politika-perf]**: Mutation check "kembalikan policy SW/Analytics ke timer pendek" scheint **lulus** (test hijau) padahal sumbernya sudah dimutasi → **Root Cause**: suite Playwright berjalan terhadap `next start` (build produksi), sedangkan mutasi hanya menyentuh file sumber; bundle lama masih tersaji, jadi test tidak pernah melihat perubahan → **Invariant Rule**: mutasi apa pun pada perilaku client harus disertai `pnpm run build` ulang SEBELUM menjalankan suite; test yang lulus di atas build lama bukan bukti apa pun. Verifikasi mutasi harus dibuktikan dengan output kegagalan yang eksplisit (mis. request analytics muncul di dalam page-load window), bukan dengan asumsi "seharusnya gagal".

- **[26-10-23 · blog/design-tokens]**: Halaman `/blog` dan `/blog/[slug]` memakai `text-muted`, `border-warm`, `bg-tint`, dan `prose` yang tidak pernah terdefinisi → **Root Cause**: halaman blog ditambahkan tanpa melewati blok `@theme` di `globals.css`, dan Tailwind v4 membuang utility yang tidak punya token tanpa satu pun error; `prose` juga tidak punya plugin `@tailwindcss/typography`, sehingga body MDX tampil tanpa gaya dan copy-nya hard-coded Inggris di rute `/id` → **Invariant Rule**: setiap kelas warna harus berasal dari token `--color-*` di `@theme`, halaman baru wajib mengambil copy dari `PortfolioContent` (bukan ternary `lang === "en"`), dan body MDX memakai `.post-body`. Buktikan dengan `curl` yang mencari nama kelas mati di HTML, bukan dengan membaca JSX.

- **[26-10-20 · test/regresi-perf]**: Menambahkan test regresi "SW/Analytics menunggu gestur pertama" sebagai jaring pengaman kebijakan mount-on-interaction → **Invariant Rule**: perubahan kebijakan performa yang sudah terukur harus dikunci test yang gagal saat kebijakan dikembalikan (mutation check wajib dijalankan minimal sekali sebelum test dianggap sahih); assertion harus observes Network request sungguhan, bukan hanya state React internal.

- **[26-10-23 · test/contact-action]**: Submit kedua di `/en/contact` tidak pernah mengirim request, dan limiter sempat dituduh "tidak bekerja" → **Root Cause**: dua lapis. (1) React 19 mereset field tak-terkontrol setelah form action selesai, jadi submit berikutnya gagal validasi `required` dan dibatalkan browser tanpa error apa pun; (2) hitungan run pengujian sebelumnya masih di dalam jendela 60 detik, sehingga submit pertama run baru sudah ditolak dan test menunggu pesan yang salah → **Invariant Rule**: uji alur form berulang wajib mengisi ulang semua field wajib dan menunggu jendela rate limit benar-benar kosong sebelum menyimpulkan perilaku server; dan batas in-memory per-proses bukan rate limit di serverless — pakai store bersama (Upstash) dan buktikan dengan dua request nyata yang kedua ditolak.

- **[26-10-25 · blog/hljs]**: Pipeline MDX memasang `rehype-highlight` sejak awal tapi tidak ada satu pun rule `.hljs-*` di `globals.css`; artikel pertama kebetulan tanpa blok kode sehingga tidak terlihat sampai artikel ber-kode pertama dirender tanpa warna token → **Root Cause**: plugin menghasilkan kelas, bukan warna; kelas tanpa rule = netral → **Invariant Rule**: setiap plugin styling yang dipasang di pipeline konten harus dibuktikan dengan konten nyata yang memicunya (tulis blok kode + `curl` kelas `.hljs-keyword` di HTML) pada commit yang sama, atau jangan pasang pluginnya.

- **[26-10-25 · ui/fork-desain]**: Halaman contact tumbuh sebagai "situs kedua" (palet hex sendiri, serif, copy hard-code Inggris, layout terpusat) dan lolos semua gate karena test tidak memeriksa konsistensi desain, hanya fungsi → **Root Cause**: verifikasi bersifat per-perilaku; tidak ada gate yang menyatakan "semua warna dari token, semua copy dari kamus" → **Invariant Rule**: halaman baru wajib memakai chrome standar (SkipLink/ThemeToggle/LanguageSwitch) dan copy dari `PortfolioContent`; saat review, grep hex literal dan string berbahasa di JSX halaman `[lang]` — keduanya adalah bau fork desain sebelum menjadi satu.

- **[26-10-25 · tema/light-kontras]**: Menggeser tema light ke hue hangat (kertas) membuat `live` (0.55) jatuh ke 3.96:1 sebagai teks kode hljs dan `signal` hampir menyatu dengan kertas → **Root Cause**: token yang semula hanya "titik dekoratif" dipromosikan jadi warna teks oleh fitur baru (hljs, pesan galat form) tanpa diukur ulang → **Invariant Rule**: setiap kali token berubah peran menjadi teks kecil (< 18px), ukur ulang kontrasnya terhadap canvas secara nyata (canvas sampling, seperti test `theme contrast`); jangan mewarisi angka lightness dari peran lamanya.
