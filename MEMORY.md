### 🧠 Learned Invariants & Failure Post-Mortems

- **[26-10-14 · app/globals.css]**: A light theme could not be added while colours lived outside the token block: the stylesheet held 17 hard-coded `oklch()` literals (white-alpha hairlines and veils, `btn-primary` hover greys, the nav-pill glass, the lightbox backdrop, the scroll-progress mid stop, the tilt glare) and three TSX files held four more inside Tailwind arbitrary values and an inline gradient → **Root Cause**: dark-only literals are invisible reviewers of a theme change — a `prefers-color-scheme` block can only re-point *tokens*, so every literal was a surface that silently stayed dark (a white-alpha hairline becomes invisible on paper, a white specular glare vanishes on white) → **Invariant Rule**: Before writing a second palette, lift every literal into `@theme` as a *role* (`--color-veil-*, line-hover, grid-line, glare, panel-translucent, backdrop, shadow-soft/deep, ink-hover/active, accent-mid, selection-*`) and prove the inventory is empty with `grep -rnE "oklch\(|#[0-9a-fA-F]{3,8}" components app`, leaving only the per-scheme `themeColor` hexes and the manifest.

- **[26-10-14 · app/globals.css / verification]**: After minifying, the light block was present in the production bundle but that fact alone proved nothing about precedence, and dev-server rendering can differ from the shipped artifact → **Root Cause**: Tailwind emits theme variables into `@layer theme`, and cascade precedence — not source order — decides whether an override wins; an unlayered `:root` rule beats every layer, but only the built CSS shows that → **Invariant Rule**: Prove a theme override on the built artifact: locate the byte offsets (`grep -bo "@layer theme"` vs `grep -bo "prefers-color-scheme:light"`) to confirm the block is both later *and* unlayered, then serve `next start` on a spare port and measure the rendered page there — a build exit 0 and a present-in-bundle string are not evidence that a scheme resolves.

- **[26-10-14 · contrast measurement]**: A verdict of "all colours pass" would have been wrong twice: `--color-ink-faint` measured 4.06:1 in dark mode across 43 text nodes (10–12px labels) and the light `--color-accent` measured 4.38:1 as 11px text, both under the 4.5 floor; a first UI-border probe reported `pass: true` while printing a 1.54 ratio → **Root Cause**: token values were chosen by eye for hierarchy, never derived from the AA floor, and translucent colours were compared as raw channels instead of composited over their own backdrop, so the number and the verdict came from different inputs → **Invariant Rule**: Never estimate contrast — compute it by compositing each ancestor's `background-color` (canvas fillStyle + `getImageData` gives non-premultiplied alpha, so alpha stacks correctly) under every text node's own colour, and derive the bottom step of the faint ramp and any accent used as small text from the 4.5:1 result rather than from taste.
